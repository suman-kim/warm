작성 2026-10-15. 이 문서 하나만 읽고 디자인할 수 있게 썼다. 기존 디자인 파일(`MOVO Apps v4.dc.html`, `MOVO Prototype v4.dc.html`, `MOVO Admin.dc.html`)의 디자인 시스템을 그대로 이어서 쓴다.

## 0. 받고 싶은 결과물

- 지금까지와 같은 형식의 디자인 파일: **`MOVO Delivery v1.dc.html`** (앱별로 화면을 묶고, 화면마다 이름을 붙인다) + 흐름을 따라가는 프로토타입.
- 화면마다 **빈 상태 · 불러오는 중 · 오류** 상태를 함께 그린다. 숫자는 아래 "예시 데이터"를 쓴다.

- 안드로이드 하단 시스템 바(제스처 바·버튼)와 겹치지 않게 하단 버튼 아래에 여백을 둔다.

## 1. 무엇이 바뀌었나

MOVO는 퀵·화물(오토바이~5톤 트럭) 매칭 앱이었다. 화물차 중개에는 운송주선사업 허가가 필요해서 **음식점 배달대행**으로 사업을 바꾼다.

- **가게(사장님)** 가 손님 주소로 배달을 요청한다 → **라이더(오토바이)** 가 가게에서 음식을 받아 손님에게 전한다.
- 배달대행료는 가게가 **미리 충전해 둔 충전금에서 배달마다 빠진다** (카드 등록·건별 카드 결제 없음).
- 음식값은 배달앱에서 **선결제**됐거나, 라이더가 손님에게 **만나서 받는다(현금 또는 카드 단말기)**.
- 라이더 한 명은 **동시에 3건까지** 맡을 수 있다 (묶음배송).
- MOVO가 직접 가게와 라이더를 모으고 운영한다 (지역 지사 없음).

## 3. 디자인 시스템 (그대로 유지)

**디자인 시스템은 바꾸지 않는다. 바뀌는 것은 화면 구성과 흐름(배달대행 특화)뿐이다.** 새 화면에 필요한 부품(배달 보드 카드, 진행 중 n/3 표시, 만나서 결제 금액 표시 등)은 아래 색·글꼴·모서리·간격으로 만든다.

- 색: lime `#C6F432`(강조·주요 버튼), ink `#121212`, paper `#F7F6F2`(밝은 바탕), night `#0F1012`(어두운 바탕), white, 밝은 바탕 위 라임 글자 `#5A7A00`, 위험·취소 `#B3261E` / 바탕 `#F8E4E1`, 어두운 바탕의 위험 `#FF7B6B` / `#3A2522`. 어두운 면 `#1A1C1F`, `#26292D`.
- 글꼴: **SUIT** (400~800). 숫자는 고정폭 숫자.
- 로고: `mov●`(라임 점) + 앱 구분 꼬리표(지금 '기사' 꼬리표처럼 → '사장님', '라이더').
- 기존 부품을 쓴다: 큰 둥근 카드, 아래 고정 주요 버튼, 아래에서 올라오는 시트, 칩, 단계 표시, 상단 바(뒤로 가기), 하단 탭.
- 문구: 해요체, 짧게. 금액은 `23,000원`, 거리 `1.3km`, 시각 `오후 7:32`.

## 4. 배달 한 건의 흐름과 상태 이름

```
가게: 배달 요청 ──(대행료가 충전금에서 빠짐)──▶ 배차 대기
라이더: 수락 ─▶ (가게 도착) ─▶ 픽업 완료 ─▶ 전달 완료 (만나서 결제면 받은 방식·금액 입력)
가게: 픽업 전까지 취소 가능 → 대행료가 충전금으로 돌아옴
```

| 서버 상태 | 가게에 보일 이름 | 라이더에게 보일 이름 |
|---|---|---|
| REQUESTED | 라이더 찾는 중 | (콜 목록) |
| ASSIGNED / DEPARTED | 라이더 배정 · 가게로 오는 중 | 가게로 이동 |
| ARRIVED | 라이더 가게 도착 | 가게 도착 |
| PICKED_UP | 배달 중 | 손님에게 이동 |
| DELIVERED | 배달 완료 | 완료 |
| CANCELLED | 취소됨 | 취소됨 |

- 서버는 '출발'·'가게 도착' 단계를 지원하지만 건너뛸 수 있다. 권장 라이더 단계: **수락 → 가게 도착 → 픽업 완료 → 전달 완료**.
- 취소: 픽업 전까지. 라이더가 출발한 뒤 취소하면 대행료의 15%를 빼고 돌려준다 (임시 규칙, 화면에 "지금 취소하면 수수료 ○원"을 보여 줄 수 있다).

## 5. 화면 목록

표시: 🆕 새로 · ✏️ 지금 화면 고침 · 📝 문구만 고침

### A. 가게 앱 (모바일, 밝은 테마)

1. 🆕 **가게 등록** — 상호, 사업자등록번호(하이픈 자동), 가게 전화, 가게 주소(지금 주소 검색 화면 재사용) + 상세주소(층·호). 이 주소가 모든 배달의 픽업지라는 안내.
2. 🆕 **심사 대기 / 반려** — 대기: "승인되면 알려 드릴게요". 반려: 사유를 보여 주고 [정보 고쳐서 다시 신청].
3. 🆕 **홈 (배달 현황)** — 충전금 잔액(부족하면 경고), 오늘 요청·완료 건수, 진행 중 배달 카드 목록(상태·손님 동·경과 시간·라이더 이름), 큰 [배달 요청] 버튼. 빈 상태: "아직 요청한 배달이 없어요".
4. 🆕 **배달 요청** (한 화면 또는 단계)
   - 손님 주소 검색 + 상세주소, 손님 연락처(안심번호 가능)
   - 음식값(원), 결제 방식: **선결제 / 만나서 현금 / 만나서 카드**
   - 조리 완료까지: 바로 · 10분 · 15분 · 20분 · 30분 · 직접 입력(최대 180분)
   - 요청사항(최대 500자)
   - **견적**: 거리·예상 시간·배달대행료, 요청 뒤 남을 잔액 / 잔액 부족이면 [충전하기]
   - 요청 완료 → 배달 상세로
5. ✏️ **배달 상세·추적** (지금 고객 '배송 추적' 화면 개편) — 단계 표시, 지도(가게·손님·라이더 위치), 라이더 이름·전화·차량번호, 픽업 예정·도착 예정 시각, 손님 주소·연락처·음식값·결제 방식, [배달 취소](픽업 전, 사유 입력, 수수료 안내). 완료 뒤에는 받은 방식·금액 표시.
6. ✏️ **배달 내역** — 날짜별 목록(손님 동, 상태, 대행료), 완료·취소 필터.
7. 🆕 **충전금** — 잔액, [충전하기](금액 1만~200만 원, 빠른 선택 5만·10만·30만), 내역 목록(충전 +, 대행료 −, 환불 +, 운영자 조정 ±, 각 줄에 잔액·관련 배달·메모). 충전 결제 방식(가상계좌·카드)은 아래 9번 결정에 따른다.
8. 📝 **마이** — 가게 정보 수정(승인 뒤 사업자번호는 고객센터로), 알림 설정, 공지·약관·고객센터·사업자 정보, 로그아웃·탈퇴. 하단 탭: 홈 · 내역 · 충전금 · 마이 (제안).

**가게 앱에서 빼는 것:** 홈의 퀵·화물 서비스 카드, 차종 선택, 화물 정보(무게·수량·계단·운반 도움), 카드 등록·결제수단 관리, 최근 보낸 경로(→ 손님 주소 최근 기록으로 바꿀지는 선택).

### B. 가게 PC 웹 (카운터, 1440)

1. 🆕 로그인
2. 🆕 **배달 보드** — 상태별 칸(라이더 찾는 중 / 가게로 오는 중 / 배달 중 / 완료·취소(오늘)), 카드에 손님 동·경과 시간·라이더, 잔액 표시, 자동 새로고침.
3. 🆕 **빠른 배달 요청** — 보드 옆 패널이나 모달. 키보드만으로 입력(주소 검색 → 상세 → 연락처 → 음식값 → 결제 방식 → 조리 시간 → Enter), 견적 실시간 표시.
4. 🆕 **배달 상세** (옆 패널) — 지도, 라이더 정보, 취소.
5. 🆕 내역(기간 검색) · 충전금 · 가게 정보.

### C. 라이더 앱 (모바일, 어두운 테마)

1. ✏️ **가입·서류·심사** — 오토바이 기준. 서류: 운전면허, 이륜차 사용신고필증, 유상운송(배달용) 이륜차 보험 증권(검토 중).
2. ✏️ **홈** — 운행 켜기·끄기, 오늘 수입·완료 건수, **진행 중 n/3**.
3. ✏️ **콜 목록 · 새 콜** — 가게 이름, 픽업 동 → 배달 동, 거리, 금액(9번 결정), 조리 완료 시각("15분 뒤 픽업"), **음식값과 결제 방식 — 만나서 현금·카드는 눈에 띄게**. [수락]. 3건을 맡고 있으면 "진행 중 배달을 먼저 끝내 주세요".
4. 🆕 **진행 중 배달 (묶음)** — 맡은 최대 3건 목록, 각 건의 단계와 다음 할 일, 같은 가게 건은 묶어 보이기(제안).
5. ✏️ **배달 진행** — 가게로 길안내(카카오내비) → [가게 도착] → [픽업 완료] → 손님에게 길안내·전화 → [전달 완료]. 요청사항·상세주소 크게.
6. 🆕 **만나서 결제** — 받을 금액을 크게, 받은 방식(현금 / 카드), 받은 금액(기본값 = 음식값, 고칠 수 있음) → [완료]. 선결제면 이 화면 없이 바로 완료.
7. 📝 **수입·정산·배달 내역·마이** — 화물 문구 정리. 배달 상세에 받은 현금·카드 표시.

**라이더 앱에서 빼는 것:** 추가 요금 입력(과적·큰 짐·계단), 대기료·노쇼 신고, 차종 선택(오토바이만).

### D. 관리자 웹 (지금 것에 추가)

1. 🆕 **가게 심사** — 목록(심사 대기·승인·반려, 상호·사업자번호 검색), 상세(사장님 이름·이메일, 가게 정보, 지도), [승인] / [반려 + 사유].
2. 🆕 **가게 충전금** — 잔액, 내역, [조정](+/− 금액, 사유 필수, 0원 아래 불가).
3. ✏️ **배달 관제** — 진행 중 배달, 오래 배차 안 된 건·픽업 지연 표시(서버 추가 예정).
4. 🆕 **라이더 현금 수금** — 만나서 결제로 받은 현금과 가게에 넘겼는지 (서버 추가 예정).
5. 📝 기존 화면(기사 심사·회원·공지·정산·운영자) 문구 정리 — '기사' → '라이더', '고객' → '가게'.

## 6. 입력 규칙과 오류 문구 (서버와 같아야 한다)

| 전화번호 | 0으로 시작하는 9~11자리 (하이픈 자동) |

| 조리 완료까지 | 0~180분 |
| 요청사항 | 500자까지 |
| 배달 거리 | 가게에서 10km까지 |

| 상황 | 화면에 보일 문구 |
|---|---|
| 승인 전 요청 | 가게 승인이 끝나면 배달을 요청할 수 있어요. |

| 받은 금액 없이 완료 | 손님에게 받은 방식과 금액을 넣어 주세요. |

| 로그인 5번 실패 | 로그인을 여러 번 실패해서 잠시 막았어요. ○분 뒤에 다시 시도하거나 비밀번호를 찾아 주세요. |

## 7. 배달대행료 (임시 — 화면 예시용)

- 2km까지 **3,500원**, 넘으면 1km마다 **+500원**, 밤 10시~아침 6시 **+500원**.
- 라이더는 대행료에서 수수료 10%를 뺀 금액을 받는다 (임시).

## 9. 아직 정하지 않은 것 (디자인은 기본값으로, 다른 안은 옆에 작게)

1. **손님 추적 링크** — 손님에게 "배달 중" 문자와 추적 웹 링크를 보낼지. 기본값: 첫 버전에는 없음 (넣는다면 손님용 추적 웹 한 화면 추가).
2. **라이더 콜의 금액** — 기본값: 라이더가 받는 몫(수수료 뺀 금액)을 크게, 대행료는 작게.
3. **충전 방식** — 기본값: 가상계좌 입금(번호 발급 → 입금하면 자동 충전) + 카드 충전 둘 다.
4. **취소 수수료** — 기본값: 라이더가 출발한 뒤 15%. 음식 배달에 맞게 바뀔 수 있다.

## 10. 우선순위

1. 가게 앱: 가게 등록 → 심사 상태 → 홈 → 배달 요청 → 배달 상세 → 충전금
2. 라이더 앱: 새 콜 → 진행 중 배달(묶음) → 배달 진행 → 만나서 결제
3. 관리자 웹: 가게 심사 → 충전금 조정
4. 가게 PC 웹: 배달 보드 → 빠른 배달 요청
5. 나머지 문구 정리
