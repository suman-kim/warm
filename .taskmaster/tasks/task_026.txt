# Task ID: 26
# Title: 디자인 화면에 맞춘 서버 기능 구현
# Status: done
# Dependencies: 8, 10
# Priority: high
# Description: 디자인(design/MOVO Apps v2)의 31개 화면이 쓰는 기능 가운데 서버에 없거나 어긋나던 것을 서버에 구현하고, 공용 API 클라이언트를 맞췄다.
# Details:
기준: 화면이 맞고 서버가 따라간다.
바뀐 계약(앱에 영향): 가입에 약관 동의 필수 · 차종 5종(5톤 삭제), 다마스 400kg · 기사 등록에서 면허 번호 삭제(서류 3종으로 대체) · 화물은 종류(category) 필수 · 견적은 POST /orders/estimates 한 번에 차종별 요금 · 수락 전 기사에게는 구·동과 약 1km로 흐린 좌표만.
새 모듈: account(탈퇴), address(자주 쓰는 주소), content(공지·약관·고객센터). 마이그레이션 AddAppFeatures(테이블 12개 추가).
임시 구현(포트 뒤, 출시 전 교체): 경로·거리·시간 어림(EstimatedRoutePlanner → 작업 29) · 인증 코드 발송(LoggingResetCodeSender, 운영에서는 전달 안 됨 → 작업 28) · 서류 파일 디스크 보관(LocalFileStorage → 작업 30) · 수수료·정산(→ 작업 27) · 요금표(→ 작업 16).
없는 것: 결제(작업 15), 약관 본문(작업 31), 주소 검색·지도(작업 32), 탈퇴 뒤 남는 개인정보 정리(작업 33).
자세한 규칙과 API 표는 backend/README.md, 앱에서 챙길 것은 packages/movo_api/README.md.

# Test Strategy:
backend: 단위 150개(도메인 규칙·유스케이스·계층 규칙), e2e 47개(실제 PostgreSQL — 주문·기사·계정·알림·콘텐츠·스키마), migration:check. 마이그레이션은 옛 데이터가 든 DB에 적용·되돌리기·재적용까지 확인.
packages/movo_api: 단위 58개, 실서버 통합 14개(tool/integration_test.sh). 고객 앱은 iOS 시뮬레이터, 기사 앱은 Android 에뮬레이터에서 스모크(가입·토큰 보관·서류 업로드).

# Subtasks:
## 1. 회원: 약관 동의·내 정보 수정·비밀번호 찾기·탈퇴 [done]
### Dependencies: None
### Description: 가입할 때 약관 동의를 받고, 계정 관리 기능을 채웠다.
### Details:
POST /auth/register에 agreements{terms,privacy,marketing} 필수(동의 시각 저장). 비밀번호 규칙: 8자 이상, 영문+숫자.
PATCH /users/me(이름·휴대폰·마케팅 수신). POST /auth/password-reset/request·confirm(6자리 코드, 10분, 5회, 1분 재발송 제한, 코드는 해시만 저장, 성공 시 모든 기기 로그아웃).
POST /users/me/withdraw(비밀번호 확인, 진행 중 주문·배송이 있으면 409, 회원의 이름·이메일·휴대폰·비밀번호 삭제, 같은 이메일로 재가입 가능 — 서류 파일·정산 계좌 등은 남는다(작업 33)).

## 2. 기사: 서류·심사·차량 변경·운행 시간·위치·정산 계좌 [done]
### Dependencies: None
### Description: 기사 가입 화면과 홈·마이 화면이 쓰는 기능.
### Details:
서류 3종(운전면허증·자동차등록증·화물운송 종사 자격증)을 모두 올려야 신청. PUT /drivers/me/documents/:type(multipart, 사진·PDF 10MB, 형식은 파일 내용으로 판단). 반려 시 rejectedDocuments로 문제 서류를 짚으면 그것만 다시 올린다.
승인·반려는 푸시(DRIVER_APPROVED/REJECTED)와 알림함으로 간다. POST /drivers/me/vehicle-change(운행을 끈 뒤, 재심사).
GET /drivers/me에 onlineSince·todayOnlineSeconds. PUT /drivers/me/location. GET/PUT /drivers/me/settlement-account(계좌번호는 끝 4자리만 응답).

## 3. 주문: 화물 종류·구/동·차종별 견적·최근 보낸 곳 [done]
### Dependencies: None
### Description: 배송 요청 화면과 콜 화면의 정보 범위를 맞췄다.
### Details:
화물 category(DOCUMENT/BOX/SHOPPING_BAG/FURNITURE_APPLIANCE/ETC) 필수, description 선택. 픽업지·도착지에 sigungu·dong.
POST /orders/estimates → 거리·시간·경로 + 차종별 요금. GET /orders/recent-destinations. GET /orders에 serviceType 필터와 driverName.
대기 콜(open-orders)은 pickupArea/dropoffArea(구·동)와 흐린 좌표만 — 주소·연락처·요청 사항은 수락 뒤에. GET /dispatch/open-orders/:id(새 콜 푸시용).

## 4. 배송 추적·길안내·예정 시각 [done]
### Dependencies: None
### Description: 기사 위치로 픽업·도착 예정 시각을 어림한다.
### Details:
수락할 때 기사 위치 → 픽업지 소요 시간으로 estimatedPickupAt, 거기에 운행 시간을 더해 estimatedDeliveryAt.
GET /orders/:id/tracking(고객·배차된 기사, 진행 중에만 기사 위치). GET /dispatch/orders/:id/navigation(픽업 전엔 픽업지, 뒤엔 도착지).
주기적 조회(폴링) 방식이다. 경로는 어림값(작업 16에서 길찾기 API로).
